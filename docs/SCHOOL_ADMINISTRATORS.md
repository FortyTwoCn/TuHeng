# 学校多管理员与最少保留规则

2026-11-19。起始代码 `776f37b`，在原学校管理和凭据交付流程内增量修改，无数据库结构迁移。

## 行为与实现

- 新建学校原本已使用 `createSchoolWithAdmin` 原子创建首位校管、加密临时凭据和审计，继续保留并验证。
- `createSchoolAdministrator` 取消每校只允许一个的限制。多个账号各自拥有唯一登录 ID、密码、首次设置状态和凭据批次，不复用教师身份或共享密码。
- `domain/identity.ts` 提供数量策略；组织查询返回操作能力供页面展示。`organization.ts` 在学校行锁内重新读取账号和本校启用校管数量，最后一个启用校管不能停用。其他学校、停用账号不计入保留数量。
- 网站管理员可在停用学校中先补建/启用校管。启用学校同样受行锁保护，并检查校管数量。操作不改变学校管理员的学校归属和教学/评分授权。
- 学校详情持续保留“创建学校管理账号”，提供最后一位校管的禁用说明。管理账号仍必须首次改密并验证邮箱；随机临时密码沿用限时安全交付。

## 回归依据

在修改实现前，新增的四项集成回归均失败：没有数量能力信息、最后校管可停用、追加第二位被 `SCHOOL_ADMIN_EXISTS` 拒绝、无校管学校可启用。修改后相应用例通过。

`tests/integration/school-administrators.test.ts` 验证建校即创建账号与凭据、拒绝停用不产生部分写入、两个并发停用仅一个成功、同校/跨校/已停用范围、旧停用学校补建与恢复。原 `teaching-organization.test.ts` 的并发补建用例改为验证两次创建均成功且登录 ID、凭据、审计独立。

`tests/e2e/school-teaching.spec.ts` 用真实表单创建学校和管理员，直接 API 尝试停用最后校管并检查 409，验证多个账号的重置/停用/启用，并在手机宽度实际提交新增第三位校管。界面覆盖桌面、平板和手机；未替代真实硬件测试。
