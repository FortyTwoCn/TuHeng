# CAD 核心性能

## 五区工作区实测（2026-11-24）

在 Ryzen 9 8940HX、Windows、Chromium 158.0.8127.37、1440 × 900 浏览器视口实测 1952 个图元。与其他回归并行运行，统计从 SVG 收到 pointermove 到第二次 requestAnimationFrame 的时间。双编辑器夹具中，24 次共享节点拖动的 P95 为 33.8 ms，32 次双指缩放输入的 P95 为 44.3 ms。登录后的独立作图页中，32 次双指缩放输入的 P95 为 23.6 ms，导出 JSON 与加载时逐项相同。前两项超过 33 ms 参考目标。测量使用浏览器模拟触点。[双实例原始数据](evidence/cad-workspace/cad-browser-performance.json) · [独立作图页原始数据](evidence/cad-workspace/cad-workspace-performance.json)

## 已有引擎基线


在 Windows x64、AMD Ryzen 9 8940HX、Node.js 26.13.0 上，从仓库根目录运行 `node --import tsx scripts/cad-benchmark.ts`。下面是一次本机执行结果。每组操作先执行 12 次，再记录 120 次同步核心调用的墙钟耗时。每次捕捉使用不同位置、4 CSS px/mm，开启对象捕捉、方向、网格与投影对齐。框架为三视图，几何对象位于同一视图。捕捉的几何索引按当前文档复用。

| 图纸 | 图元组成 | 连续捕捉 中位/P95 ms | 40 条共享节点线段平移预览 中位/P95 ms | 撤销再重做 中位/P95 ms |
| --- | --- | --- | --- | --- |
| 409 个对象 | 140 点、256 线段、各 3 个圆、弧、椭圆、样条、1 个剖面 | 0.2645 / 0.6700 | 0.0938 / 0.1122 | 0.0003 / 0.0003 |
| 1952 个对象 | 646 点、1239 线段、17 圆、17 弧、16 椭圆、16 样条、1 个剖面 | 0.7795 / 5.0784 | 0.2031 / 0.2938 | 0.0002 / 0.0002 |

以本机 P95 小于 8 ms 作为上述图纸的核心计算参考预算。该预算给浏览器的输入处理、React 提交与绘制留下时间。撤销及重做在已校验的文档快照间切换，其统计只包括历史容器调用。表中数据均不包括浏览器渲染、截图、触摸输入调度或页面端到端帧耗时。测试图纸并不模拟数百条线完全重合于一点的极端局部密度。真实移动设备需另测。

## 计算路径

线、圆、圆弧、椭圆及其区间、Hermite 样条使用图纸毫米几何。筛选候选时先使用当前指针的邻域与几何包围盒，再计算邻域内的交点。圆锥曲线使用有理二次曲段，样条使用三次曲段，曲线修剪保存原始参数区间。与直线及圆锥曲线的交点、垂足、切点使用多项式根隔离。样条之间的交点使用控制区间的极值包围盒、区间细分及 Newton 校正。重合、无法可靠定位、计算预算耗尽的区域不会生成可接受的修剪结果。

捕捉距离随屏幕 CSS 像素缩放，求交精度使用固定图纸单位。曲线求值和界面渲染之间不传递屏幕采样点作为正式对象。预览使用未提交文档，正式提交才运行完整校验。

## 浏览器输入与绘制

同一台 Windows 电脑上使用 Chromium 158.0.8127.37、生产模式 React、并排两个编辑器。以下时间从 SVG 收到一次 `pointermove` 起算，直到第二个 `requestAnimationFrame` 回调执行，包含浏览器等待帧的时间。采用 Playwright 鼠标移动和 CDP 双指输入。测试会在松开前核对可见几何及正式文档，且确认双指缩放只改变相机。

| 图纸及输入 | 样本数 | 中位数 ms | P95 ms | 最大值 ms |
| --- | ---: | ---: | ---: | ---: |
| 513 个对象，鼠标拖动端点 | 31 | 5.4 | 9.8 | 21.0 |
| 缓存前，1952 个对象，鼠标拖动共享节点 | 24 | 22.3 | 24.9 | 25.0 |
| 缓存前，1952 个对象，双指放大 | 32 | 23.0 | 51.7 | 51.8 |
| 缓存后，1952 个对象，鼠标拖动共享节点，三个浏览器进程各测一次 | 每次 24 | 6.7–8.5 | 9.0–15.3 | 21.3–25.0 |
| 缓存后，1952 个对象，双指放大，三个浏览器进程各测一次 | 每次 32 | 2.9–4.2 | 12.0–45.0 | 12.0–45.0 |

SVG 渲染按图纸版本建点索引。有限线段由视口裁剪，只有无限线需要随相机重新求边界。未变的图元子树、曲线和剖面的绘制路径可以跨手势复用。点标记保持 6 CSS px 的几何直径，另有线宽。

桌面典型输入 P95 的优化目标是 33 ms。缓存后的三次双指样本分别为 12.0、29.3、45.0 ms，一次超过目标。首次测量启用了 Playwright 的失败回放记录，最后三次计时关闭回放和视频，避免全图 DOM 快照影响延迟。两阶段数据包含这一测量设置差异。该数据采自并行验收环境，不能推断低端设备或 Apple Pencil 的延迟。小图样本由 `geometry-components.spec.ts` 中的性能用例产生。复杂样本可单独执行 `npx playwright test tests/e2e/cad-performance.spec.ts`。复杂测试覆盖 1440×900 窗口、正式提交前实时预览及提交后相机操作。[复杂样本原始记录](evidence/cad/complex-browser-performance.json)

### 最终生产构建

在独立测试数据库下启动 Next.js 生产构建，学生从登录页进入 `/geometry`，导入 1952 个对象，以双指扩大视图，再由文件菜单导出。三个独立 Chromium 进程各执行一次，每次取得 32 个触摸事件样本，三份导出文档都与输入图纸完全一致。并排双编辑器的拖动与缩放也各重复三次，合计六个浏览器用例通过。测量期间同一台电脑另有三组浏览器回归在运行。

| 正式验收时的场景 | 各次 P95 ms | 各次中位数范围 ms |
| --- | --- | --- |
| 实际练习页，双指放大 | 36.3、52.9、44.0 | 8.9–19.2 |
| 双编辑器，鼠标拖点 | 27.3、38.3、42.1 | 15.0–24.8 |
| 双编辑器，双指放大 | 44.3、67.2、38.3 | 9.4–14.7 |
| 同机浏览器回归结束后再次单独测量实际练习页，双指放大 | 39.0、57.8、65.5 | 3.3–3.8 |

并行与单独测量时，实际练习页六次双指 P95 都高于 33 ms。单独执行的三个用例也通过了缩放和导出一致性断言。真实 Android、iPad、电子笔和移动设备的特定帧率仍待实机测量。[最终构建的原始样本](evidence/cad/release-browser-performance.json)
